## 1. 변경
| 항목 | 내용 |
|---|---|
| CI(GitHub Actions) | main push·PR마다 lint·typecheck, 설치 스크립트 검사(shellcheck·PowerShell 구문), 단위 테스트, test:db(postgres:17), 빌드, 이미지 빌드 + 빈 Linux 설치(`install.sh`·승계 1~12)·백업·복구를 자동으로 돌린다(CR-13). E2E는 로컬 게이트 |
| CD(GitHub Release) | 판을 올린 커밋이 main CI를 통과하면 판 태그를 자동으로 달고, Linux 오프라인 번들(`termflow-linux-<판>.tar.gz`·`.sha256`)을 만들어 **번들만으로 빈 폴더 설치**를 확인한 뒤 GitHub Release 초안에 올린다(CR-14). 판 번호 확인 `scripts/release-check.sh` |
| 설치·운영 가이드 | §14.2·§14.5 — 번들을 GitHub Release에서 내려받는 경로 추가(직접 `bundle.sh`로 만드는 방법은 그대로) |
| 소개 사이트 | 화면·기능 페이지 배치(그림 옆 설명·영역별 요약), 공개 배포(Vercel Git 연동) |
| 정리 | 설명서 화면의 lint 경고(`v-html` 예외 주석 범위) — 동작 변경 없음 |

## 2. 업그레이드
v1.1.1에서 바뀐 제품 동작은 없다(DB·포트·설정 그대로). 평소 절차(가이드 §6 Windows · §14.5 Linux `upgrade.sh`)로 올리면 된다. 번들은 이 판부터 GitHub Release에서 받을 수 있다.

## 3. 알려진 제한
- Release는 **초안**으로 만들어진다 — 첨부 파일을 확인한 뒤 Releases 화면에서 게시한다.
- Windows용 배포물(이미지 포함 zip)은 아직 없다 — Windows는 소스 + `start.bat -Build`(CR-14 C10).
