# TermFlow 테이블 설계 가이드

- 판: 1.0 (2026-10-15)
- 적용: TermFlow로 테이블을 설계하는 모든 사람과 외부 에이전트(`/mcp` 연동)
- 관련: 설계서 §5(자동완성·네이밍 규칙 엔진)·§5.7(검증 규칙)·§6.6(DEFAULT), CR-18(외부 에이전트 연동), 사용자 가이드 §9

## 0. 이 문서가 필요한 이유

TermFlow는 **기능**을 제공한다. 자동완성이 `exact`·`similar`·`composed`·`unregistered` 중 무엇을 내든, 사람이 타입을 직접 고치든, 기본컬럼을 빼든 저장할 수 있다. 어느 것을 먼저 고르고 언제 예외를 허용하는지는 지금까지 사람의 판단에 맡겨 왔다.

외부 에이전트는 그 판단 기준을 모른다. 기능이 허용하는 길 가운데 가장 빨리 끝나는 길(조합·수동 타입·기본컬럼 생략)을 고르기 쉽다. 이 문서는 그 판단 기준을 **우선순위와 예외 조건**으로 적는다.

- 사람에게는 표준 관행이다.
- 에이전트에게는 **반드시 따라야 하는 규칙**이다. 예외는 이 문서가 정한 조건을 만족하고 사용자 확인을 받은 경우에만 허용한다.

규칙 문장의 강도는 다음과 같이 읽는다.

| 표기 | 뜻 |
|---|---|
| **필수** | 어기면 설계 결함이다. 에이전트는 예외 없이 지킨다. |
| **원칙** | 예외 조건(문서에 명시)을 만족하고 사용자 확인을 받은 경우에만 벗어난다. 벗어난 사유는 설계물에 기록한다. |
| **권장** | 더 나은 방법. 따르지 않아도 결함은 아니다. |

## 1. 핵심 원칙

| 번호 | 원칙 | 강도 |
|---|---|---|
| P1 | 물리명·타입·길이는 **표준 사전(용어·도메인분류·도메인·코드)에서 나온다**. 손으로 짓거나 고치지 않는다. 사전에 없으면 사전에 먼저 넣고 다시 자동완성을 받는다. | 필수 |
| P2 | 컬럼 매칭은 **§2.2 우선순위**를 따른다. 위 단계가 가능하면 아래 단계로 내려가지 않는다. | 필수 |
| P3 | **같은 의미의 컬럼은 모든 테이블에서 같은 도메인**을 쓴다. 키·참조(FK)·조인 컬럼은 반드시 도메인으로 묶는다. | 필수 |
| P4 | 값의 집합이 정해진 컬럼(코드성 컬럼)은 **코드구분에 연결**한다. | 필수 |
| P5 | 프로젝트 **기본컬럼 세트는 모든 테이블에 넣는다**. | 원칙 |
| P6 | 접미어 기본 타입과 다른 타입이 필요하면 컬럼에서 고치지 않고 **도메인을 만들어** 그 도메인을 쓴다. | 필수 |
| P7 | `table_validate`(편집기 검증)의 **오류 0건·경고 0건**에서 저장한다. 경고를 남길 때는 사유를 테이블 설명에 적는다. | 원칙 |
| P8 | 표준 사전 변경(용어·도메인·코드 등록·수정)은 프로젝트 전체에 영향이 있다. 에이전트는 **등록안을 표로 보여 주고 확인을 받은 뒤** 등록한다. | 필수 |

## 2. 컬럼 설계

### 2.1 논리명 짓기

1. 논리명은 **등록된 표준 용어의 조합**으로 짓고, 마지막 조각은 **도메인분류 접미어**(타입을 정하는 말)로 끝낸다.
   - 예: `사이트` + `ID` → 사이트ID, `수신` + `시각` → 수신시각, `설비` + `구분` + `코드` → 설비구분코드
2. 접미어는 값의 성격으로 고른다. 프로젝트마다 도메인분류가 다를 수 있으므로 `domain_classes_list`(화면: 표준 사전 > 도메인분류)로 확인한다. 기본 표준 템플릿(STDV1) 기준으로 헷갈리기 쉬운 것은 다음과 같다.

| 값의 성격 | 접미어(물리) | 기본 타입 | 고르는 기준 |
|---|---|---|---|
| 문자열 식별자 | ID | VARCHAR(50) | 키·참조 값 |
| 숫자·문자 섞인 번호 | 번호(NO) | VARCHAR(30) | 사업자번호·LOT번호처럼 계산하지 않는 번호 |
| 일련 정수 | 순번(SEQ) | INT | 같은 상위 키 안에서 1, 2, 3… |
| 개수 | 수·건수(CNT) | INT | 세는 값 |
| 정렬 | 순서(ORD) | SMALLINT | 표시·정렬 순서 |
| 이름 | 명(NM) | VARCHAR(100) | |
| 코드값 | 코드(CD) | VARCHAR(10) | 코드구분에 연결(§2.5) |
| 코드성 분류 | 구분(TP)·유형(CLS)·상태(STAT)·등급(GRD)·종류(KIND)·분류(CTG)·판정(JGMT) | VARCHAR(10) | 값 집합이 정해져 있으면 코드구분 연결(§2.5) |
| Y/N | 여부(YN) | VARCHAR(1) | |
| 날짜 | 일자(DT) | VARCHAR(8) | YYYYMMDD 문자열 |
| 초 단위 시점 | 일시(DTS) | TIMESTAMP(0) | 업무 일시 |
| 밀리초 시점 | 시각(TS) | TIMESTAMP(3) | 장비·통신 이벤트 시점 |
| 금액 | 금액(AMT) | BIGINT | 원 단위 정수 |
| 수치 | 값(VAL)·수치(NVAL) | NUMERIC(18,4) | 계산·측정 값 |
| 버전 | 버전(VER) | VARCHAR(20) | `1.2.3`처럼 문자열 버전 |

3. **같은 의미에 다른 접미어를 섞지 않는다.** 예를 들어 프로젝트에서 이벤트 시점을 `시각(TS)`으로 정했으면 다른 테이블에서 같은 성격을 `일시(DTS)`로 짓지 않는다.
4. 값의 성격에 맞는 접미어가 없으면 **도메인분류(접미어)를 먼저 등록**한다(프로젝트 관리자). 기존 접미어와 뜻이 겹치는 새 접미어는 만들지 않는다.

### 2.2 매칭 우선순위 — 자동완성 결과를 어떻게 쓰는가

컬럼마다 `columns_autocomplete`(편집기: 논리명 입력 후 Enter) 결과를 받아 **위에서부터** 처리한다.

| 순위 | 결과·상황 | 처리 | 저장되는 matchType |
|---|---|---|---|
| 1 | `exact` | `applied`를 그대로 쓴다. 타입·길이를 고치지 않는다. | EXACT |
| 2 | 코드성 컬럼(§2.5) | `codeCandidates`에서 코드구분을 고른다. 맞는 코드구분이 없으면 코드구분을 등록하고 다시 받는다. 도메인이 정확일치하면 `domainId`도 함께 둔다. | CODE |
| 3 | `similar` 후보 중 **뜻이 같은** 도메인이 있음 | 논리명을 그 도메인의 논리명으로 바꾸고 다시 자동완성 → `exact`로 받는다. (같은 뜻을 다른 이름으로 부르지 않기 위해 — P3) | EXACT |
| 4 | `similar` 후보 중 뜻이 같은 것이 없음, `composed`, 또는 위 단계를 못 씀 | §2.3 기준으로 **도메인 등록 대상인지** 판단한다. 대상이면 도메인을 등록하고 다시 자동완성 → `exact`. | EXACT |
| 5 | §2.3에서 도메인 등록 대상이 아님 | `composed`의 `applied`(조각 물리명 + 접미어 타입)를 그대로 쓴다. | COMPOSED |
| 6 | `unregistered` | 저장하지 않는다. §4 절차로 용어를 등록하고 다시 자동완성한다. | (저장 금지) |
| — | 타입·물리명을 손으로 입력 | **하지 않는다.** 필요한 타입은 §2.4대로 도메인으로 만든다. | MANUAL(쓰지 않음) |

- `similar` 후보를 고르고 논리명을 그대로 두면 matchType이 SIMILAR로 남는다. 논리명과 도메인 이름이 달라 같은 뜻의 이름이 둘이 되므로 **3순위 방식(논리명을 도메인 이름으로 맞춤)을 쓴다**.
- 접미어가 도메인분류에 없어 `composed`의 타입이 비면(`W_SUFFIX_UNREGISTERED`) 타입을 손으로 넣지 않는다. §2.1-4대로 접미어를 등록한다.

### 2.3 도메인으로 등록해야 하는 컬럼

`composed`로 받은 컬럼이라도 다음 중 **하나라도** 해당하면 도메인을 등록한 뒤 `exact`로 쓴다(**필수**).

| 조건 | 이유 |
|---|---|
| D1. PK, 또는 다른 테이블을 가리키는 컬럼(FK·조인 키) | 양쪽 테이블의 타입·길이가 반드시 같아야 한다 |
| D2. 프로젝트의 둘 이상의 테이블에 나오는 컬럼(이미 나왔거나 나올 것) | 같은 뜻을 한 곳에서 관리해야 한 번에 바꿀 수 있다 |
| D3. 접미어 기본 타입·길이와 다른 타입이 필요한 컬럼 | §2.4 — 수동 타입은 도메인에만 둔다 |
| D4. 값 범위·단위·형식 같은 업무 규칙이 있는 컬럼 | 도메인 설명에 규칙을 적어 재사용한다 |

`composed`를 그대로 둬도 되는 경우는 **한 테이블에만 나오고, 접미어 기본 타입이 맞고, 키가 아닌** 서술성 컬럼뿐이다(예: 그 테이블에만 있는 `사이트설명`).

도메인 등록 절차(프로젝트 관리자):
1. `domain_classes_list`로 접미어 확인
2. `domain_calculate {nm1..nm7}` 미리보기 — 조각이 모두 등록 용어인지, 같은 논리명 도메인이 이미 있는지 확인
3. `domain_create` → 컬럼에서 다시 자동완성(`exact`)

### 2.4 타입을 접미어 기본값과 다르게 정해야 할 때

수동 타입 결정은 **예외**다. 순서대로 판단한다.

1. **다른 접미어로 해결되는가?** 정수 일련값이면 `번호(NO, VARCHAR)` 대신 `순번(SEQ, INT)`, 개수면 `수(CNT)`처럼 성격에 맞는 접미어를 고르면 수동 타입이 필요 없다. 이것이 1순위다.
2. **접미어 자체가 프로젝트에 맞지 않는가?** 프로젝트 전체에서 그 접미어의 타입이 달라야 하면(예: 모든 `코드`가 VARCHAR(20)) 도메인분류의 타입을 바꾸고 `domains_recalculate`로 재계산한다(프로젝트 관리자, 사용자 확인).
3. **이 의미 하나만 다른가?** 그 의미의 도메인을 등록하면서 타입을 수동(MANUAL)으로 지정하고, **도메인 설명에 사유**를 적는다(예: "외부 연계 API의 siteNo가 정수 — INT").
4. 컬럼 행에서 타입만 고치는 것(`W_DOMAIN_TYPE_CHANGED`)과 MANUAL 컬럼은 쓰지 않는다.

### 2.5 코드성 컬럼

1. 값의 집합이 정해져 있고 업무 규칙이 그 값에 따라 달라지는 컬럼은 **코드성 컬럼**이다. 이름이 `…코드`이거나 코드성 접미어(구분·유형·상태·등급·종류·분류·판정)로 끝난다.
2. 코드성 컬럼은 **코드구분에 연결**한다(`codeClsId`, matchType CODE).
   - 맞는 코드구분이 없으면 코드구분과 코드값을 먼저 등록한다(`code_class_create`·`code_create`, 프로젝트 관리자). 코드값을 모르면 사용자에게 묻는다. 빈 코드구분을 만들지 않는다.
   - 코멘트에 코드구분을 적는다(예: `설비 구분 (DP/001)`). 자동완성 후보의 `colComment`가 이 형식이다.
3. 예외 — 코드구분에 연결하지 않는 경우:
   - **코드 마스터 테이블의 키**: 경보코드 테이블의 `경보코드`처럼 그 테이블 자체가 코드 목록이면 키 컬럼은 도메인(EXACT)으로 둔다.
   - **열린 값**: 외부 시스템이 정하는 임의 문자열(태그 항목 등)은 코드성 컬럼이 아니다. 이름에 `코드`를 쓰지 말고 성격에 맞는 접미어(명·값 등)로 짓는다.
4. 숫자 등급·상태(1 긴급·2 주의…)도 값이 정해져 있으면 코드성 컬럼이다. 타입만 맞추려고 도메인을 INT로 만들고 코드구분을 생략하지 않는다.

### 2.6 기본컬럼(감사 컬럼)

1. 새 테이블에는 프로젝트 **기본 세트**(`project_settings_get`의 `defaultColSetId`, `default_column_set_get`)의 컬럼을 **전부, 세트 순서대로, 컬럼 끝에** 넣는다.
   - 에이전트: 각 컬럼의 `defaultColId`를 유지하고 matchType DEFAULT, `columnId`는 null.
   - 화면: 프로젝트 설정 "기본컬럼 포함"이 켜져 있으면 테이블 편집기가 새 테이블에 자동으로 넣는다.
   - **주의**: 이 자동 포함은 편집기 화면의 동작이다. API(`table_create`)는 기본컬럼을 넣어 주지 않으므로 에이전트는 직접 넣어야 한다.
2. 기본컬럼과 같은 이름의 컬럼을 손으로 만들지 않는다(`defaultColId` 없이 같은 물리명을 넣지 않는다).
3. **이력·로그 테이블도 넣는 것이 원칙이다.** 기록 시점이 필요하면 기본컬럼의 `최초등록일시`로 충분한지 먼저 본다. 별도 시각 컬럼(예: 장비가 알려 준 발생시각)은 의미가 다를 때만 둔다.
4. 예외(기본컬럼을 빼거나 다른 세트를 쓰는 경우)는 **사용자가 명시적으로 지시한 경우에만** 허용한다. 테이블 설명에 `기본컬럼 제외: <사유>`를 적는다.
   - 예외가 될 수 있는 경우: 외부 도구가 구조를 정한 테이블(마이그레이션 도구의 적용 이력 등), 초당 수천 건 쌓이는 원시 수집 테이블처럼 저장량이 문제가 되는 경우

### 2.7 PK·NULL·기본값·코멘트

| 항목 | 규칙 | 강도 |
|---|---|---|
| PK | 모든 테이블에 PK를 둔다(`W_PK_NONE` 금지). PK 컬럼은 NOT NULL. | 필수 |
| NULL | 업무상 반드시 있어야 하는 값은 NOT NULL. 모르면 NULL 허용으로 두고 설명에 적는다. | 원칙 |
| 기본값 | 문자열은 따옴표 없이(`N`), 숫자는 그대로, 함수는 `CURRENT_TIMESTAMP`·`CURRENT_DATE`만(설계서 §6.6). | 필수 |
| 코멘트 | 논리명을 되풀이하지 말고 의미·단위·값 범위·코드구분·원천을 적는다(예: `포트 1 ~ 65535`, `수위(m)`). | 권장 |

## 3. 테이블 설계

1. **업무구분**을 먼저 정한다(`biz_areas_list`). 테이블은 반드시 하나의 업무구분에 속하고 물리명은 그 접두어로 시작한다.
2. **테이블 물리명**은 `table_name_suggest {logicalNm, bizAreaId}` 결과를 쓴다. `complete=false`면 미등록 조각을 §4대로 등록하고 다시 받는다. 손으로 고치지 않는다.
3. **테이블 논리명**도 등록 용어의 조합으로 짓는다. 성격을 나타내는 말(마스터·이력·내역·원장 등)을 일관되게 쓴다.
4. **테이블 설명**(필수): 무엇을 기록하는지, 한 행이 무엇인지, 원천(원래 테이블·시스템)을 적는다. 이 문서의 예외(기본컬럼 제외·경고 유지)를 썼다면 그 사유도 적는다.
5. 컬럼은 §2, 저장은 `table_validate` 오류·경고 0건(P7) 뒤 `table_create`/`table_save`.

## 4. 용어 등록

1. **중복 확인**: `terms_check`로 같은 한글·물리약어가 있는지 확인한다. 뜻이 같은 기존 용어가 있으면 그 용어를 쓴다(동의어를 새로 만들지 않는다).
2. **약어 관례 확인**: `standards_search`로 비슷한 기존 용어의 약어를 보고 관례(영문 약어 길이·모음 생략 방식)에 맞춘다. 물리약어는 영대문자·숫자.
3. **등록안 확인**(에이전트 필수): 한글명·물리약어·설명을 표로 보여 주고 사용자 확인을 받는다.
4. **등록**:
   - 편집자: `term_request` → 검토대기(PENDING). 즉시 설계에 쓸 수 있고 `W_TERM_PENDING` 경고가 남는다.
   - 프로젝트 관리자: `term_create` → 바로 승인(APPROVED).
5. **승인**(프로젝트 관리자): 승인 큐(`approvals_list`)에서 약어를 고쳐 승인하거나 사유를 적어 반려한다. 반려된 용어를 쓴 컬럼은 `W_TERM_REJECTED`로 표시되므로 다시 설계한다.
6. 용어를 등록한 뒤에는 그 용어가 들어간 컬럼을 **다시 자동완성**한다(물리명을 손으로 이어 붙이지 않는다).

## 5. 외부 에이전트 작업 규칙

에이전트는 §1~§4에 더해 다음을 지킨다.

**시작 전**
- `whoami`로 역할 확인. 편집자면 용어는 `term_request`만 가능하고, 도메인·코드구분·도메인분류 등록은 프로젝트 관리자에게 요청해야 한다는 것을 사용자에게 알린다.
- `project_settings_get`·`biz_areas_list`·`default_column_sets_list`·`domain_classes_list`를 읽고 시작한다.
- 요구사항이 모호하면 도구를 부르기 전에 묻는다: 테이블 목적, 한 행의 의미, 키, 다른 테이블과의 관계.

**설계 중**
- 테이블·컬럼 논리명 목록을 먼저 만들어 보여 준다(§2.1).
- 자동완성 결과를 §2.2 순위로 처리한다. 순위 4·5(도메인 등록 여부)의 판단 결과를 컬럼마다 남긴다.
- 사전 등록(용어·도메인·코드구분·도메인분류)은 **한 번에 모아 등록안 표**로 보여 주고 확인을 받는다.
- 여러 테이블을 설계하면 공통 컬럼(키·참조 컬럼, 시각 컬럼)을 먼저 뽑아 도메인으로 등록한 뒤 테이블을 만든다(D1·D2).

**하지 않는 것**
- 물리명·타입·길이를 직접 짓거나 고치기, MANUAL 컬럼
- 접미어 기본 타입과 다른 타입을 컬럼에서 바꾸기(→ 도메인, §2.4)
- 코드성 컬럼을 코드구분 없이 두기(→ §2.5 예외만)
- 기본컬럼 생략(→ 사용자 지시가 있을 때만, §2.6)
- 경고를 남긴 채 저장하고 보고하지 않기

**완료 보고** — 테이블마다 다음을 보여 준다.

| 항목 | 내용 |
|---|---|
| 매칭 통계 | EXACT n · CODE n · COMPOSED n · DEFAULT n · SIMILAR 0 · MANUAL 0 |
| COMPOSED 사유 | 컬럼마다 "한 테이블 전용 서술 컬럼" 등 §2.3 판단 근거 |
| 사전 변경 | 등록한 용어·도메인·코드구분·도메인분류 목록 |
| 예외 | 기본컬럼 제외·남긴 경고와 사유(없으면 없음) |
| 검증 | 오류 0 · 경고 0 |

## 6. 저장 전 점검표

- [ ] 업무구분·테이블 물리명은 자동 제안 결과다.
- [ ] 테이블 설명에 목적·한 행의 의미·원천이 있다.
- [ ] PK가 있다.
- [ ] MANUAL·SIMILAR·UNREGISTERED 컬럼이 없다.
- [ ] 키·참조 컬럼과 여러 테이블에 나오는 컬럼은 모두 EXACT(도메인)다.
- [ ] COMPOSED 컬럼은 §2.3 예외 조건(한 테이블 전용·기본 타입·키 아님)을 만족한다.
- [ ] 코드성 컬럼은 CODE(코드구분 연결)이거나 §2.5 예외다.
- [ ] 기본 세트 기본컬럼이 끝에 모두 있다(또는 사용자 지시 + 설명에 사유).
- [ ] 기본값 형식이 맞다(따옴표 없음).
- [ ] `table_validate` 오류 0 · 경고 0.

## 7. 사례 — DPMS 점검(2026-10-15)

테스트 서버의 실 프로젝트 DPMS(배수펌프장 통합운영관리, 31개 테이블)는 에이전트가 설계했다. 모든 테이블이 검증 오류·경고 0건으로 저장됐지만, 이 가이드 기준으로는 다음 문제가 있다. **검증 경고 0건이 설계 품질을 보장하지 않는다**는 것이 이 문서를 만든 직접 계기다.

| 가이드 | 발견 | 가이드대로라면 |
|---|---|---|
| P5·§2.6 | 기본 세트 "표준 감사"(8컬럼)를 쓴 테이블은 31개 중 11개뿐(세트 참조 88건 = 11×8). `DP_MEAS_HST`·`DP_SCRPT_APPLY_HST` 등 20개는 기본컬럼이 없고 설명에 사유도 없다. 프로젝트 설정 "기본컬럼 포함"은 켜져 있었지만 그 설정은 편집기 화면에만 적용된다. | 모두 넣거나, 사용자 지시가 있으면 설명에 `기본컬럼 제외: 사유` |
| P3·§2.3 D1·D2 | 여러 테이블의 키·참조 컬럼 `SITE_ID`·`GW_ID`·`LINK_ID`가 COMPOSED(도메인 없음) | 사이트ID·게이트웨이ID·링크ID 도메인 등록 후 EXACT |
| §2.1-3·§2.3 D2 | 도메인분류 `시각(TS)`을 새로 만들었으나 도메인 0개 — `수신시각`·`PLC시각`·`게이트웨이감지시각`·`적용시각` 등이 모두 COMPOSED | 반복되는 시각 컬럼은 도메인으로 등록 |
| §2.4 | 접미어 기본 타입과 다른 도메인: `게이트웨이사이트번호` INT(번호 NO = VARCHAR(30)), `매핑표버전` INT(버전 VER = VARCHAR(20)) — 설명에 사유 없음 | 정수 값이면 성격에 맞는 접미어(순번 등) 검토, 아니면 MANUAL 도메인 + 사유 |
| §2.5-4 | `경보등급` INT 도메인(등급 GRD = VARCHAR(10), 코드성) — 값이 1 긴급·2 주의·3 알림으로 정해져 있는데 코드구분 없음 | 코드구분 등록 후 CODE |
| §2.5-3 | `역할코드`(ROLE_CD) — `…코드`이지만 값이 태그에서 뗀 열린 문자열(LEVEL_IN · CURRENT …), 코드구분 없음 | 이름에서 `코드`를 빼고 성격에 맞는 접미어로 |
| §2.6-3 | `DP_SCRPT_APPLY_HST`의 `적용시각`은 기본컬럼 `최초등록일시`와 같은 역할 | 기본컬럼으로 대체 검토 |

잘 지킨 점: 코드성 컬럼 다수(`워드순서코드`·`명령쓰기방식코드`·`설비구분코드`·`경보범위코드` 등)가 코드구분에 연결(CODE)됐다. 코드 마스터 키 `GT_ALRM_CD.ALRM_CD`는 도메인(EXACT)으로 둬 §2.5-3 예외와 맞다. 기본값은 모두 형식에 맞다.

## 8. 후속

이 가이드는 판단 기준을 정한 문서다. 기준이 지켜지게 하는 장치는 다음 순서로 만든다.

1. **검증 경고 보강**(서버): 이 가이드 위반 가운데 기계적으로 판정할 수 있는 것을 경고로 만든다. 경고는 사람과 에이전트 모두에게 되돌아가는 피드백이다.
   - 기본 세트 컬럼이 빠진 테이블(프로젝트 설정 "기본컬럼 포함"이 켜져 있을 때). API 저장에도 편집기와 같은 자동 포함을 적용할지 함께 결정한다.
   - MANUAL·SIMILAR 컬럼
   - 코드성 접미어(코드 CD) 컬럼인데 코드구분 없음(코드 마스터 키 예외)
   - COMPOSED인데 PK이거나 프로젝트의 다른 테이블에 같은 물리명이 있음(D1·D2)
2. **연동 안내문·설계 절차(스킬) 반영**: 서버 안내문은 클라이언트에서 길이가 잘리므로 핵심 원칙(P1~P8)과 이 문서 위치만 남기고, 상세 절차는 에이전트용 설계 절차 문서(스킬)로 배포한다.
3. **DPMS 정리**: §7의 발견을 사용자와 확인해 고친다(기본컬럼 추가, 공통 키·시각 도메인 등록, 코드구분 정리).
