## 1. 구성 한눈에 보기

| 구성 요소 | 내용 |
|---|---|
| 컨테이너 `app` | 이미지 `termflow-app:1.1.1`(Node 22, 웹 화면 + API 한 프로세스). 호스트 포트 `TERMFLOW_APP_PORT`(기본 7340) → 컨테이너 8080 |
| 컨테이너 `db` | `postgres:17`. 호스트 포트 `TERMFLOW_DB_PORT`(기본 7341) → 컨테이너 5432. 데이터는 Docker 볼륨 `<프로젝트>_termflow-pgdata` |
| 설치 폴더 `logs\` | 애플리케이션 로그 `termflow.YYYY-MM-DD.N.log`(일 단위, 30일 보관) |
| 설치 폴더 `backup\` | `scripts\backup.ps1`이 만든 `termflow_yyyyMMdd.dump`(14일 보관) |
| 설치 폴더 `migration\report\<run_id>\` | 승계 리포트 CSV(규칙별·대사·요약·DDL 회귀) |
| 설치 폴더 `seed\original\` | 승계 원본 dump(읽기 전용, 수정 금지) |
| 설치 폴더 `.env` | 설정·비밀값(커밋·공유 금지) |

기동 순서는 `start.bat`(내부적으로 `start.ps1`)이 맡는다: ① Docker 확인 → ② `.env` 필수 값 확인 → ③ db 기동·healthy 대기 → ④ 승계 실행 여부 → ⑤ app 기동·healthy 대기(기동 시 DB 스키마 자동 적용, 최초 1회 초기 관리자 생성) → ⑥ 브라우저 열기.

## 2. 요구 사항

| 항목 | 요구 | 확인 |
|---|---|---|
| OS | Windows 10/11 64비트(Windows PowerShell 5.1 기본 포함) | `winver` |
| Docker Desktop | 4.x 이상, WSL2 백엔드, Compose v2 | `docker info` 오류 없음, `docker compose version` |
| Docker VM 메모리 | **4GB 권장**(운영 app + db 사용량은 수백 MB). 이미지 빌드와 다른 무거운 컨테이너를 동시에 돌리는 PC만 6GB. 설정: `%UserProfile%\.wslconfig`에 `[wsl2]` / `memory=4GB` / `swap=2GB` 후 `wsl --shutdown` → Docker Desktop 재시작. 올리기 전에 Windows 쪽 여유 메모리를 확인한다 | 작업 관리자의 `vmmem` |
| 디스크 | 여유 5GB 이상(이미지 약 0.4GB + postgres 이미지 + 빌드 캐시 + DB·백업) | — |
| 네트워크 | 최초 이미지 빌드 때만 인터넷 필요(Node·PostgreSQL 이미지, npm 패키지). 이후 운영은 오프라인 가능 | — |
| 포트 | 7340(app), 7341(db) 비어 있어야 함 — 흔한 서비스 기본값(8080·5432 등)과 겹치지 않게 고른 값(CR-12 C16). 겹치면 `.env`에서 바꾼다(§3.2) | `netstat -ano | findstr :7340` |
| 브라우저 | Chrome·Edge 최신 2개 버전(설계서 §12.7) | — |
| 소스 | 릴리스 `v1.0.0` 소스(저장소 복제 또는 압축 파일) | `git describe --tags` → `v1.0.0` |

Node.js·pnpm은 **운영에는 필요 없다**(이미지 빌드가 컨테이너 안에서 한다). 개발 환경은 루트 `README.md`.

## 3. 새 PC 설치

### 3.1 소스 준비
```powershell
git clone --branch v1.0.0 <저장소 주소> C:\TermFlow
# 또는 릴리스 압축 파일을 C:\TermFlow에 푼다(seed\original\ 포함 확인)
```
- `seed\original\dump-gen_table-new.sql`(약 2.1MB)이 있어야 승계를 할 수 있다.
- 설치 폴더 경로에 공백·한글이 있어도 동작한다.

### 3.2 `.env` 작성
```powershell
copy .env.example .env
notepad .env
```
**주석은 반드시 별도 줄에 쓴다.** `KEY=값   # 설명`처럼 같은 줄에 쓰면 Docker가 `# 설명`까지 값으로 읽는다(CR-11a C4, `start.ps1`이 찾아서 알려 준다).

비밀값 3개는 무작위로 만든다(값을 메일·문서에 남기지 않는다). PowerShell 창에서 실행해 나온 값을 `.env`에 붙여 넣는다.
```powershell
# 세션 키(64자 = 32바이트 난수 16진수)
$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); -join ($b | ForEach-Object { $_.ToString('x2') })
# DB 비밀번호·초기 관리자 비밀번호(영문·숫자 24자 + 특수문자 1자). 관리자 비밀번호 정책: 8~64자, 영문·숫자·특수문자 중 2종 이상, 로그인 ID 포함 금지
[guid]::NewGuid().ToString('N').Substring(0,24) + '-'
```
값에는 `#`·`$`·따옴표·공백을 쓰지 않는다(`.env` 해석 차이 방지).

`.env` 항목 전체(설계서 §2.8·§12.5, 부록 B.3):

| 변수 | 운영 값 | 필수 | 설명 |
|---|---|---|---|
| `TERMFLOW_DB_PASSWORD` | 무작위 | **필수** | DB 사용자 `termflow` 비밀번호. **최초 기동(빈 볼륨) 때 DB에 기록**되므로 이후 바꾸려면 DB에서도 `ALTER USER`가 필요하다(§12) |
| `TERMFLOW_ADMIN_LOGIN` | `admin` | 선택 | 초기 시스템 관리자 로그인 ID(최초 기동 시 사용자 0명일 때만 생성). 승계의 RMS 프로젝트 관리자 기본값 |
| `TERMFLOW_ADMIN_PASSWORD` | 무작위 | **필수** | 초기 관리자 비밀번호. **첫 로그인 때 변경이 강제**된다. 사용자가 이미 있으면 다시 쓰이지 않는다 |
| `TERMFLOW_SESSION_SECRET` | 무작위 32바이트 이상 | **필수** | 세션 쿠키 서명 키. 바꾸면 모든 사용자가 로그아웃된다 |
| `TERMFLOW_SESSION_TIMEOUT` | `60m` | 선택 | 세션 유휴 만료(분 단위 `Nm`) |
| `TERMFLOW_SECURE_COOKIE` | (생략 = `auto`) | 선택 | `auto`: 요청이 HTTPS일 때만 세션 쿠키 Secure(사내 `http://PC이름:7340` 직접 접속 가능). `true`: TLS 종단 프록시 뒤 전용(항상 Secure + `upgrade-insecure-requests`). `false`: Secure 안 씀(CR-11a C5) |
| `LOCKOUT_MAX` / `LOCKOUT_MINUTES` | (생략 = 5 / 15) | 선택 | 로그인 연속 실패 잠금 횟수·시간 |
| `TERMFLOW_UPLOAD_MAX_MB` | `10` | 선택 | 엑셀 일괄 등록 업로드 상한(MB) |
| `TERMFLOW_DEFAULT_DIALECT` | `POSTGRESQL` | 선택 | 새 프로젝트 기본 DDL 방언(v1.0은 PostgreSQL만) |
| `TERMFLOW_ORACLE_COMPAT` | `19c` | 선택 | 예약(2차 Oracle 방언) |
| `TERMFLOW_TEST_DIALECTS` | (비움) | 선택 | 개발 테스트용. 운영은 비운다 |
| `TERMFLOW_CACHE_MAX_PROJECTS` | `20` | 선택 | 자동완성 캐시에 올려 둘 프로젝트 수 상한 |
| `DB_POOL_MAX` | `10` | 선택 | DB 연결 풀 크기(동시 사용자 20명 기준) |
| `LOG_LEVEL` | `info` | 선택 | `fatal`·`error`·`warn`·`info`·`debug`·`trace`·`silent` |
| `NODE_ENV`·`PORT`·`TERMFLOW_DB_URL`·`TERMFLOW_DB_USER`·`TERMFLOW_LEGACY_DUMP`·`TERMFLOW_REPORT_DIR` | 그대로 둠 | — | **컨테이너 안에서는 `docker-compose.yml`이 고정값으로 덮어쓴다**(production, 8080, `postgres://db:5432/termflow`, `termflow`, `/seed/original/…`, `/app/migration/report`). 개발 실행(`pnpm dev`)에서만 의미가 있다 |
| `COMPOSE_PROJECT_NAME` | (주석 = `termflow`) | 선택 | Docker 프로젝트 이름. **볼륨 이름 접두어**가 된다(`<이름>_termflow-pgdata`). 설치 후 바꾸면 빈 DB로 보이므로 바꾸지 않는다 |
| `TERMFLOW_DB_CONTAINER` / `TERMFLOW_APP_CONTAINER` | (주석 = `termflow-db` / `termflow-app`) | 선택 | 컨테이너 이름. 같은 PC에 인스턴스를 둘 이상 둘 때만(§11) |
| `TERMFLOW_DB_PORT` / `TERMFLOW_APP_PORT` | (주석 = `7341` / `7340`) | 선택 | 호스트 포트. 겹칠 때만 바꾼다. v1.1.0 이하에서 기본값(5434·8080)으로 설치한 곳은 업그레이드 때 `start.bat`·`start.sh`가 옛 값을 `.env`에 적어 접속 주소를 유지한다. 값이 있으면 쿠키 이름 접미어로도 쓰인다(아래) |
| `TERMFLOW_COOKIE_SUFFIX` | (주석 = 비움) | 선택 | 로그인 쿠키 이름 접미어(`tf.sid.<값>`·`XSRF-TOKEN-<값>`). 비우면 `TERMFLOW_APP_PORT` 값, 그것도 없으면 접미어 없음. 브라우저 쿠키는 포트를 가리지 않아 **같은 서버에 포트만 다른 인스턴스**가 있으면 한쪽 로그인이 다른 쪽 세션을 끊는다 — 포트를 다르게 적으면 저절로 나뉜다(CR-15 C4). 바꾸면 그 인스턴스 사용자는 한 번 다시 로그인한다 |

`.env`는 설치 폴더 밖으로 복사하지 않는다. 파일 권한을 운영 담당자 계정으로 제한하는 것을 권장한다(탐색기 → 속성 → 보안).

### 3.3 이미지 빌드(최초 1회, 3~10분)
`start.bat`이 이미지가 없으면 자동으로 빌드하지만, 진행 상황을 보려면 먼저 따로 빌드한다.
```powershell
docker compose build app
docker image ls termflow-app      # termflow-app:1.1.1, 약 410MB
```

### 3.4 실행과 승계
```powershell
start.bat
```
- 처음 실행하면 ④에서 **"미실행: 1차 승계 … 지금 실행할까요? (y/N)"**를 묻는다. 승계 방식은 §4를 먼저 읽고 정한다.
  - 2단계(설계 기본): `y` → 1차(패션·유통 템플릿 RETAILV1) → 정정 → 다시 `start.bat` → 2차 질문 `y`(RMS·33 테이블·DDL 회귀).
  - 한 번에(§11.5 대안, v1.0.0 운영 설치에서 채택): `start.bat -Migrate yes -MigrateAll` → 1~12를 한 번에 실행하고 정정은 나중에 두 곳에서 한다. 초기 관리자가 아직 없으면 app을 먼저 기동해 만든 뒤 승계한다.
- 승계를 건너뛰면(`N`) 다음 `start.bat` 실행 때 다시 묻는다. 이미 끝난 승계는 묻지 않는다(DB에서 RETAILV1 — 1.2.0 이전 설치는 승계로 만든 STDV1 — 과 RMS 존재로 판정). 승계를 하지 않아도 범용 기본 표준 템플릿 STDV1은 app이 처음 기동할 때 만들어진다(§4.7).
- 옵션: `-Build`(이미지 다시 빌드, 업그레이드) · `-Migrate yes|no|ask` · `-MigrateAll` · `-NoBrowser` · `-TimeoutSec 300`.
- `.env`가 없거나 필수 값이 비었거나 세션 키가 32바이트 미만이면 항목별 안내를 출력하고 종료 코드 1로 끝난다.
- `start.bat`은 Windows 기본 실행 정책에서 `.ps1`을 실행하기 위한 실행기다. PowerShell에서 직접: `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 …`

### 3.5 첫 로그인
1. 브라우저가 `http://localhost:7340`(포트를 바꿨으면 그 포트)을 연다. 다른 PC에서는 `http://<PC 이름 또는 IP>:7340` — Windows 방화벽에서 해당 포트 인바운드를 허용한다.
2. 아이디 `TERMFLOW_ADMIN_LOGIN`, 비밀번호 `TERMFLOW_ADMIN_PASSWORD`로 로그인한다.
3. **비밀번호 변경 화면으로 바로 이동한다(강제).** 새 비밀번호로 바꾸면 `.env`의 `TERMFLOW_ADMIN_PASSWORD`는 더 이상 쓰이지 않는다(값을 지워도 되지만 필수 검사 때문에 임의 값은 남겨 둔다).
4. [시스템 › 사용자]에서 실제 사용자 계정을 만든다(초기 비밀번호는 화면에 한 번만 표시, 사용자는 첫 로그인 때 변경). 사용법은 `docs/사용자_가이드.md`.

## 4. 승계 본실행(초기 데이터, 최초 1회)

gen-table의 표준 사전·33 테이블을 옮긴다(설계서 §11). 대상: 패션·유통 템플릿 **RETAILV1** "패션·유통 표준 v1"(업무구분 6·도메인분류 84·용어 1,705·도메인 4,587·코드구분 159·코드 991·기본컬럼 9)과 프로젝트 **RMS**(RETAILV1 복사본 + 테이블 33·컬럼 649). 1.2.0 이전 설치에서 키 STDV1로 만든 승계 템플릿은 업그레이드 후 첫 기동 때 RETAILV1로 바뀐다(CR-16, 데이터·파생 프로젝트는 그대로).

### 4.1 방식 선택
| 방식 | 순서 | 장단점 |
|---|---|---|
| 2단계(설계 기본, §11.5) | 1차 `LOAD_LEGACY..DEFAULT_COL`(1~8) → **RETAILV1에서 정정** → 2차 `COPY_TO_RMS..DDL_REGRESSION`(9~12) | 정정이 한 번(RMS가 정정된 사본을 받는다). 정정이 끝날 때까지 RMS를 쓸 수 없다 |
| 한 번에(대안) | `LOAD_LEGACY..DDL_REGRESSION`(1~12) → 정정은 **RETAILV1·RMS 두 곳에서 각각** | 바로 RMS를 쓸 수 있다. 정정 작업이 두 배(복사 후에는 원본 변경이 전파되지 않음, C1) |

v1.0.0 운영 설치는 정정 준비(T6.14)가 끝나지 않아 **한 번에** 방식으로 실행했다(CR-10 U5, TODO 위험 K8).

### 4.2 실행
1. **실행 전 백업**(빈 DB라도 복구 기준점): db가 떠 있어야 하므로 먼저 `start.bat -Migrate no -NoBrowser`로 설치만 끝낸 뒤
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\backup.ps1
   ```
2. 승계 실행(둘 중 하나):
   ```powershell
   start.bat -Migrate yes -MigrateAll -NoBrowser              # 한 번에(1~12)
   start.bat -Migrate yes -NoBrowser                          # 2단계: 1차, 정정 후 같은 명령을 한 번 더 → 2차
   # 수동(같은 러너): docker compose run --rm app node apps/server/dist/migration/seed.js --steps=LOAD_LEGACY..DDL_REGRESSION
   ```
3. **실행 후 백업**: 같은 `backup.ps1`(같은 날 두 번째 파일은 `termflow_yyyyMMdd_HHmmss.dump`로 따로 남는다).

러너는 웹 서버와 별도의 1회성 컨테이너로 돌고(app이 떠 있어도 된다), 성공이면 종료 코드 0, 실패·대사 불일치면 1이다. 각 step은 대상이 비어 있을 때만 실행하고 아니면 SKIPPED이므로 **같은 명령을 다시 실행해도 안전**하다(대사·DDL 회귀는 매번 다시 검사).

### 4.3 결과 확인(릴리스 조건: 대사 100% + DDL 회귀 33/33)
콘솔 끝에 `[migrate:seed] 완료 … — 리포트 /app/migration/report/<run_id>`가 나오고, 설치 폴더 `migration\report\<run_id>\`에 다음이 생긴다(UTF-8 BOM, 엑셀에서 바로 열림).

### 4.4 정정(정정 담당자: 시스템 관리자)
승계 원본에는 타입을 정할 수 없는 도메인(미등록 조각·접미어)이 있어 **검토필요(review)** 로 표시된다(v1.0.0 운영: 승계 템플릿 293건 · RMS 293건). 정정은 화면에서 한다(러너 재실행 불필요).

1. 대상 보기: [표준 사전 › 도메인]에서 **검토필요** 필터(`/projects/RETAILV1/standards/domains?review=true`), 사유 열(예: "접미어 … 미등록", "미등록 조각: …"). 전체 목록은 리포트 `r05_domain_type.csv`·`r15_unregistered_parts.csv` 또는 정정 초안 xlsx.
2. 정정 초안(저장소 `migration/corrections/`): `terms.xlsx`(미등록 조각 66종 — 물리약어 칸을 채운다) · `domain-classes.xlsx`(미등록 접미어 129종 — 타입·길이를 채운다) · `domains.xlsx`(검토필요 도메인 293 + 사유 시트, 참고용). 최신 DB 기준으로 다시 만들려면 개발 PC에서 `pnpm --filter @termflow/server corrections:draft`.
3. 적용 순서(프로젝트마다): **용어** [일괄 등록] `terms.xlsx` → **도메인분류** [일괄 등록] `domain-classes.xlsx` → **도메인** [재계산 ▾ › 검토필요 도메인만](`REVIEW_ONLY`) → 남은 검토 도메인은 행 편집으로 직접 타입 지정(수기 타입).
4. **한 번에 방식이면 같은 작업을 템플릿 RETAILV1과 프로젝트 RMS에서 각각** 한다(RETAILV1은 패션·유통 업종 프로젝트의 원본, RMS는 이관 테이블이 참조하는 사본). 범용 기본 표준 STDV1은 정정 대상이 아니다(검토필요 0건).
5. 정정 뒤 확인: 도메인 화면 검토 건수 감소, RMS 테이블 편집기에서 해당 컬럼 경고(`W_DOMAIN_TYPE_CHANGED` 등) 확인 후 필요하면 [재적용]. 감소 건수는 `docs/03_TODO.md` 5절(T11.8)에 기록한다.
6. 참고: FINAL(확정) 테이블은 표준 변경으로 자동 수정되지 않는다(DDL 재현성). 고치려면 [확정 해제] → 수정 → 다시 확정.

### 4.5 CR-09 전환 스크립트(이전 이름으로 이미 만든 업무 DB가 있을 때만)
TermFlow 1.0.0부터 물리명이 용어사전 기준(`마스터 = MAST`, `등록자 = RGSRT`)이다. gen-table 시절 DDL로 **업무 DB에 실제로 만든 테이블**(`…_MST`, `FIRS/FINA_REG_USER_ID`)이 있으면 그 DB에서 한 번 이름을 바꾼다.
1. 그 업무 DB를 백업한다(`pg_dump -Fc`).
2. 대상 스키마를 `search_path`에 두고 실행: `psql -v ON_ERROR_STOP=1 -d <업무DB> -f docs\cr09_rename_postgresql.sql`(한 트랜잭션 — 테이블명 18 · 컬럼명 66 · PK 제약명 15 · CHECK 제약명은 있을 때만).
3. TermFlow에서 해당 테이블 DDL을 다시 생성해 업무 DB와 비교한다.
- TermFlow 자신의 DB(`prj_table`)는 러너가 처리하므로 이 스크립트를 실행하지 않는다. 이전 이름으로 적재된 TermFlow DB(1.0.0 이전 개발 DB)만 `docker compose run --rm app node apps/server/dist/migration/seed.js --steps=TERM_UNIFY,RECONCILE,DDL_REGRESSION`으로 정정한다.

### 4.6 legacy 스키마 보관
승계 원본은 DB 안 `legacy` 스키마에 읽기 전용으로 남는다(원본 백업 역할, 설계서 §12.4). **1차 릴리스 확정(정정 완료·사용자 테스트 G8 통과) 후** 백업을 한 번 더 받고 삭제한다.
```powershell
docker compose exec db psql -U termflow -d termflow -c "DROP SCHEMA legacy CASCADE"
```

## 6. 업그레이드

1. 사용자에게 공지하고 **백업**: `scripts\backup.ps1`.
2. 소스 교체: `git fetch --tags` → `git checkout v<새 버전>`(또는 새 압축 파일을 같은 폴더에 덮어쓰기 — `.env`·`logs`·`backup`·`migration\report`는 유지).
3. 릴리스 노트의 `.env` 변경 사항을 반영한다(`.env.example`과 비교).
4. `start.bat -Build -Migrate no` → 이미지 재빌드 → app 기동 시 **새 DB 마이그레이션 자동 적용**(로그 "마이그레이션 적용 N건"). 실패하면 app이 기동하지 않고 로그에 원인이 남는다.
5. 확인: §3.6. 되돌리기: 이전 버전 소스로 `start.bat -Build -Migrate no` 후, 스키마가 바뀐 버전이면 `restore.ps1`로 1의 백업을 복구한다.
6. **v1.1.1 기본 포트 변경**(app 8080 → 7340, db 5434 → 7341): `.env`에 포트가 없는 기존 설치는 `start.bat`이 옛 값을 `.env`에 적어 주소를 유지한다(§14.5와 같은 규칙).

## 7. 백업

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\backup.ps1            # backup\termflow_yyyyMMdd.dump
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\backup.ps1 -KeepDays 30
```
- db 컨테이너 안 `pg_dump -Fc` → `pg_restore -l` 목차 검증 → 호스트로 복사. 같은 날 다시 실행하면 `_HHmmss`가 붙은 새 파일(덮어쓰지 않음). `-KeepDays`(기본 14)보다 오래된 `termflow_*.dump`만 삭제.
- 덤프에는 `legacy` 스키마·마이그레이션 기록이 함께 들어간다(복구 후 마이그레이션 0건).
- **매일 자동 백업**(작업 스케줄러, 관리자 권한 불필요 — 경로는 설치 폴더로 바꾼다):
  ```bat
  schtasks /Create /SC DAILY /ST 02:00 /TN "TermFlow Backup" /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\TermFlow\scripts\backup.ps1"
  schtasks /Query /TN "TermFlow Backup"
  ```
  PC가 꺼져 있던 날은 건너뛴다. 스케줄러 속성에서 "예약된 시작 시간을 놓친 경우 가능한 대로 빨리 작업 시작"을 켜 둔다.
- `backup\`을 주기적으로 다른 매체(공유 폴더 등)에 복사한다 — 같은 PC 디스크 고장에 대비.
- PowerShell 파이프나 `>`로 `pg_dump` 출력을 받지 않는다(PowerShell 5.1이 바이너리를 텍스트로 바꿔 덤프가 깨진다, CR-11a C8).

## 8. 복구

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\backup.ps1                                  # 현재 상태도 먼저 백업(권장)
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\restore.ps1 -File backup\termflow_yyyyMMdd.dump
```
- 확인 문구 `RESTORE`를 입력해야 진행한다(`-Force`로 생략). 순서: app 중지 → db healthy → `termflow` DB 삭제·재생성 → `pg_restore --exit-on-error` → 건수 출력(`users= projects= tables=`) → app 기동(`-NoAppStart`로 생략).
- **새 PC·새 볼륨 복구**: §3.1~3.3(소스·`.env`·이미지) → `restore.ps1 -File <덤프>` → `start.bat -Migrate no`. `.env`의 `TERMFLOW_DB_PASSWORD`는 새 볼륨을 만들 때 쓰이므로 아무 값이나 되지만, `TERMFLOW_SESSION_SECRET`을 원래 값과 다르게 하면 기존 세션만 끊긴다(데이터 영향 없음). 사용자 비밀번호는 DB에 있으므로 그대로다.
- 복구 후 확인: 로그인, 프로젝트·테이블 건수, 필요하면 `docker compose run --rm app node apps/server/dist/migration/seed.js --steps=RECONCILE,DDL_REGRESSION`(읽기 전용 검증).

## 11. HTTPS·같은 PC의 두 번째 인스턴스

- **HTTPS**: 사내 리버스 프록시(IIS ARR·nginx 등)가 TLS를 종단하고 `http://localhost:7340`으로 넘기는 구성을 권장한다. 프록시는 `X-Forwarded-Proto: https`를 보내야 한다. 모든 접속이 HTTPS면 `.env`에 `TERMFLOW_SECURE_COOKIE=true`.
- **두 번째 인스턴스**(검증·리허설): 소스를 **다른 폴더**에 두고 그 폴더 `.env`에 `COMPOSE_PROJECT_NAME`(예 `termflow-rehearsal`)·`TERMFLOW_DB_CONTAINER`·`TERMFLOW_APP_CONTAINER`·`TERMFLOW_DB_PORT`·`TERMFLOW_APP_PORT`를 서로 겹치지 않게 지정한 뒤 같은 절차를 따른다. 볼륨·로그·백업·리포트가 폴더·프로젝트별로 분리된다. 같은 이미지(`termflow-app:<판>`)는 공유한다. 로그인 쿠키 이름은 `TERMFLOW_APP_PORT`로 나뉘므로 두 인스턴스에 같은 브라우저로 동시에 로그인해도 서로 끊기지 않는다(v1.1.2까지는 한쪽에 로그인하면 다른 쪽이 로그아웃됐다, CR-15 C4).
- 개발용 DB(개발 PC의 `termflow-db`, 5434)와 운영 인스턴스를 같은 PC에 둘 때도 운영 쪽을 별도 폴더·프로젝트 이름으로 설치한다.

## 12. 보안 운영

| 항목 | 절차 |
|---|---|
| 초기 비밀번호 | 첫 로그인 강제 변경(§3.5). 사용자 초기화 비밀번호도 첫 로그인 때 변경 |
| 비밀값 보관 | `.env`만. 문서·메일·메신저·커밋에 쓰지 않는다. 백업 매체는 DB 내용(비밀번호 해시 포함)을 담으므로 접근을 제한한다. `.env` 값은 컨테이너 환경 변수로 들어가 `docker inspect`로 보이므로, 운영 PC의 Windows 계정·`docker-users` 그룹을 운영 담당자로 제한한다 |
| 세션 키 교체 | `.env`의 `TERMFLOW_SESSION_SECRET` 변경 → `docker compose up -d app`(재생성). 전원 로그아웃 |
| DB 비밀번호 교체 | `docker compose exec db psql -U termflow -d termflow -c "ALTER USER termflow PASSWORD '<새 값>'"` → `.env` 변경 → `docker compose up -d` |
| 계정 잠금 | 연속 5회 실패 → 15분 잠금. 시스템 관리자가 [사용자]에서 [잠금 해제] |
| 의존성 점검 | 월 1회 개발 PC에서 `pnpm audit --prod`(high 이상 0 유지) → 필요하면 업그레이드(§6) |
| 포트 노출 | db 포트(7341)는 원격 접속이 필요 없으면 방화벽에서 막는다(앱은 컨테이너 네트워크로 접속) |

## 13. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| `Docker가 실행 중이 아닙니다(docker info 실패)` | Docker Desktop을 켜고 고래 아이콘이 "Engine running"이 된 뒤 다시 실행 |
| `.env 필수 값을 확인하세요` | 안내된 변수를 채운다. 값이 `#`로 시작한다는 안내면 주석을 별도 줄로 옮긴다 |
| `db 서비스를 시작하지 못했습니다` / `port is already allocated` | 포트 충돌 → `.env`의 `TERMFLOW_DB_PORT`·`TERMFLOW_APP_PORT` 변경 |
| app이 healthy가 안 됨 | `docker compose logs --tail 100 app`: 환경 변수 검증 실패(누락 변수 이름이 나온다), 마이그레이션 오류, DB 비밀번호 불일치(`password authentication failed` — 볼륨을 처음 만들 때의 비밀번호와 `.env`가 다름 → §12의 `ALTER USER` 또는 원래 값으로) |
| 승계 러너 `RMS 프로젝트 관리자 'admin' 사용자가 없습니다` | 초기 관리자가 없는 상태에서 2차·한 번에 실행 → `start.bat -Migrate no`로 app을 한 번 기동한 뒤 다시(`start.ps1`은 자동 처리) |
| 승계 러너 종료 코드 1 | 콘솔의 FAILED step·대사 항목 확인 → `migration\report\<run_id>\summary.csv`·`reconcile.csv`. 원인 수정 후 같은 명령 재실행(끝난 step은 SKIPPED) |
| 로그인 후 바로 로그인 화면으로 돌아옴 / CSRF 403 | HTTPS 프록시 없이 `TERMFLOW_SECURE_COOKIE=true`로 둔 경우 → `auto`(생략)로 |
| 다른 PC에서 접속 안 됨 | Windows 방화벽 인바운드 규칙(TCP 7340), 주소 `http://<PC이름>:7340` |
| 화면이 옛 버전 | 업그레이드 후 브라우저 강력 새로고침(Ctrl+F5) |
| 디스크 부족 | `docker system df` → 오래된 빌드 캐시 `docker builder prune`(볼륨은 지우지 않는다), `backup\` 외부 이동 |
| 로그인 잠금(423)·비밀번호 분실 | 15분 대기 또는 다른 시스템 관리자가 [사용자]에서 잠금 해제·비밀번호 초기화. 초기 관리자는 사용자 0명일 때만 만들어지므로 **시스템 관리자를 2명 이상** 지정해 둔다 |

## 14. Linux 서버 설치(v1.1.0, CR-12)

Windows와 **같은 이미지·같은 `docker-compose.yml`·같은 `.env`** 를 쓴다(CR-12 C6). 스크립트만 Linux용이다: `install.sh`(최초 설치·업그레이드) · `start.sh`(= `start.ps1`) · `scripts/backup.sh`·`scripts/restore.sh`(= `.ps1`) · `scripts/bundle.sh`(오프라인 번들 만들기). 명령은 설치 폴더(예 `/opt/termflow`) 기준이다.

### 14.1 요구 사항
| 항목 | 요구 | 확인 |
|---|---|---|
| OS | x86-64 Linux. systemd가 있으면 부팅 시 기동·백업 타이머를 등록한다(없으면 건너뛰고 cron 예시를 안내) | `uname -m` → `x86_64` |
| Docker | Docker Engine + compose 플러그인 v2(`docker compose`). 배포판 패키지 예: Ubuntu·Debian `docker.io` + `docker-compose-v2`, 또는 Docker 공식 `docker-ce` + `docker-compose-plugin`(<https://docs.docker.com/engine/install/>) | `docker info`, `docker compose version` |
| 권한 | `sudo`(systemd 등록) — root가 아니면 그 사용자를 `docker` 그룹에 넣고 다시 로그인(`sudo usermod -aG docker <사용자>`) | `docker ps`가 sudo 없이 동작 |
| 메모리·디스크 | 메모리 2GB 이상, 디스크 여유 5GB 이상(번들 압축 약 230MB, 풀면 이미지 약 1GB) | `free -h`, `df -h` |
| 포트 | 7340(app)·7341(db). 겹치면 `install.sh --port`·`--db-port`(처음 설치 때) 또는 `.env` | `ss -ltnp` |
| 네트워크 | 인터넷이 되면 소스만 받아 서버에서 빌드할 수 있다. **폐쇄망은 오프라인 번들**(§14.2) | — |

### 14.2 설치 파일 준비
**A. 오프라인 번들(권장, 폐쇄망 가능)** — 번들 = `git archive`(커밋된 소스·seed·문서, 개발 도구 설정 제외) + `images/termflow-images-<판>.tar.gz`(`docker save termflow-app:<판> postgres:17`). 판은 `docker-compose.yml`의 app 이미지 태그에서 읽는다.

- **GitHub Release에서 받기(v1.1.1부터)**: 저장소 Releases의 해당 판(예 `TermFlow v1.1.1`)에서 `termflow-linux-<판>.tar.gz`와 `.sha256` 두 파일을 인터넷이 되는 PC로 내려받는다(비공개 저장소라 GitHub 로그인 필요). 이 파일은 버전 태그를 push하면 자동으로 만들어지고, 전체 검사(CI)와 "번들만으로 빈 서버 설치" 확인을 통과한 것이다(CR-14).
- **직접 만들기**(Release가 없거나 태그 전 판): 개발 PC(Windows는 Git Bash, 이미지 `termflow-app:<판>`이 있어야 한다)에서 아래를 실행한다.

```bash
scripts/bundle.sh            # 이미지가 없으면 --build. 결과: release/termflow-linux-<판>.tar.gz + .sha256
```

**서버로 옮기기** — 두 파일이 있는 폴더(Release에서 받았으면 내려받은 폴더, 직접 만들었으면 `release/`)에서 서버 `/tmp/`로 보낸다(Windows 10/11은 PowerShell·cmd에 `scp`·`ssh`가 기본으로 있다. 서버 계정·주소는 실제 값으로):
```bash
scp release/termflow-linux-1.1.1.tar.gz release/termflow-linux-1.1.1.tar.gz.sha256 <계정>@<서버 주소>:/tmp/
ssh <계정>@<서버 주소>
```
SSH가 막힌 폐쇄망이면 USB·사내 파일 전송 등으로 같은 두 파일을 서버 `/tmp/`에 둔다.

**서버에서 처음 설치** — 체크섬 확인 → 설치 폴더에 풀기 → 설치(§14.3):
```bash
cd /tmp && sha256sum -c termflow-linux-1.1.1.tar.gz.sha256
sudo mkdir -p /opt/termflow
sudo tar -xzf /tmp/termflow-linux-1.1.1.tar.gz -C /opt/termflow --strip-components=1 --no-same-owner
sudo /opt/termflow/install.sh
```
이미 설치된 서버는 풀지 말고 업그레이드 한 줄(§14.5)을 쓴다. 설치가 끝나면 `/tmp/`의 번들은 지워도 된다(설치 폴더 `images/`에 이미지 사본이 남는다).
**B. 소스 받기(인터넷 필요)**: `sudo git clone --branch v1.1.1 <저장소 주소> /opt/termflow` — 이미지는 첫 기동 때 서버에서 빌드한다(3~10분, node 이미지·npm 패키지를 받는다).

### 14.3 `install.sh`
```bash
sudo /opt/termflow/install.sh                          # 기본: 초기 데이터(승계)는 묻는다
sudo /opt/termflow/install.sh --migrate yes --migrate-all   # 묻지 않고 승계 1~12 한 번에(§4.1 대안)
```
순서: ① 환경 확인(Linux·Docker·compose·seed) → ② `images/*.tar.gz` 있으면 `docker load` → ③ `.env`가 **없을 때만** `.env.example`에서 만들고 `NODE_ENV=production`, 비밀값 3개(`TERMFLOW_DB_PASSWORD` 32자 · `TERMFLOW_ADMIN_PASSWORD` 영문·숫자 22자 + `-` + 숫자 · `TERMFLOW_SESSION_SECRET` 16진수 64자)를 `/dev/urandom`으로 채운다(**화면에 내지 않는다, 권한 600**) → ④ compose가 쓸 이미지 확인(없고 소스도 없으면 중단) → ⑤ root + systemd이면 단위 등록(§14.6) → ⑥ `./start.sh`(§3.4와 같은 6단계: db → 승계 질문 → app healthy).

| 옵션 | 뜻 |
|---|---|
| `--port N` · `--db-port N` | 앱·DB 호스트 포트(`.env`를 새로 만들 때만 반영. 이후는 `.env`의 `TERMFLOW_APP_PORT`·`TERMFLOW_DB_PORT`) |
| `--migrate ask\|yes\|no` · `--migrate-all` | `start.sh`로 넘긴다(§3.4·§4) |
| `--no-systemd` · `--no-start` | 서비스 등록 생략 · 설치만(기동은 나중에 `./start.sh`) |
| `--write-units 폴더` | systemd 단위 파일을 그 폴더에 쓰기만 한다(검토용) |

- **다시 실행해도 된다**: 있는 `.env`·DB 볼륨·등록된 서비스는 그대로 두고 빠진 것만 채운다(업그레이드도 같은 명령, §14.5).
- `logs/`·`migration/report/`는 컨테이너의 `node` 사용자(uid 1000)가 쓴다. `start.sh`가 root로 돌면 소유자를 1000으로 맞추고, 다른 사용자로 돌면 쓰기 권한을 연다(안 되면 `sudo chown 1000:1000 logs migration/report`).
- `start.sh` 옵션: `--migrate ask|yes|no` · `--migrate-all` · `--build`(소스로 다시 빌드) · `--timeout 초`. 브라우저는 열지 않고 주소만 출력한다.

### 14.4 첫 로그인·확인
1. 초기 관리자 비밀번호 확인(설치 담당자만): `sudo grep ^TERMFLOW_ADMIN_PASSWORD= /opt/termflow/.env`
2. 브라우저 `http://<서버 주소>:7340` → `admin` + 위 비밀번호 → **강제 비밀번호 변경**(§3.5). 방화벽: `sudo ufw allow 7340/tcp` 또는 `sudo firewall-cmd --add-port=7340/tcp --permanent && sudo firewall-cmd --reload`.
3. 확인은 §3.6과 같다: `docker compose ps`(둘 다 healthy) · `curl -s localhost:7340/health` · 로그인 화면의 [사용자 가이드] 링크(`/manual`) 열림.

### 14.5 업그레이드
사용자에게 공지한 뒤, 새 판 번들을 준비해(§14.2 — GitHub Release에서 받거나 `bundle.sh`로 만든다) 서버로 옮기고 업그레이드 스크립트 한 줄을 실행한다.
```bash
# 개발 PC
scp release/termflow-linux-1.1.1.tar.gz release/termflow-linux-1.1.1.tar.gz.sha256 <계정>@<서버 주소>:/tmp/
ssh <계정>@<서버 주소>
# 서버
sudo bash /opt/termflow/scripts/upgrade.sh /tmp/termflow-linux-1.1.1.tar.gz
```
`upgrade.sh` 순서: ① 번들 확인(옆에 `.sha256`이 있으면 검증, TermFlow 번들인지·판) → ② **백업**(db가 떠 있으면 `scripts/backup.sh`, 실패하면 중단) → ③ 설치 폴더에 풀기(이전 판 이미지 파일은 지운다. `.env`·`backup/`·`logs/`·`migration/report/`는 번들에 없어 그대로) → ④ `install.sh --migrate no`(새 이미지 적재 → app을 새 이미지로 다시 만들고 기동 시 DB 마이그레이션 자동 적용, §6). 옵션: `--no-backup`, 그 밖의 옵션은 `install.sh`로 넘긴다.

- **v1.1.1보다 옛 설치(`scripts/upgrade.sh`가 없음)** 는 한 번만 수동으로: `sudo bash /opt/termflow/scripts/backup.sh` → `sudo tar -xzf /tmp/termflow-linux-<판>.tar.gz -C /opt/termflow --strip-components=1 --no-same-owner` → `sudo /opt/termflow/install.sh --migrate no`. 다음부터는 위 한 줄.
- 소스(git) 설치는 `git fetch --tags && git checkout v<새 판>` → `./start.sh --build --migrate no`.
- 확인: `docker compose ps`(healthy) · `docker image ls termflow-app`(새 판) · 로그 "마이그레이션 적용 N건" · 사이드바 아래 판 표시.
- 되돌리기: 이전 판 번들로 같은 `upgrade.sh`를 실행 → 스키마가 바뀐 판이었으면 ②의 백업으로 복구(§14.6).

v1.0.0 → v1.1.x 업그레이드는 DB 변경이 없다(마이그레이션 0건). **v1.1.1에서 기본 포트가 app 8080 → 7340, db 5434 → 7341로 바뀌었다** — `.env`에 포트를 적지 않고 옛 기본값으로 쓰던 설치는 `start.sh`(`install.sh`가 부른다)·`start.bat`이 기동 전에 옛 값(`TERMFLOW_APP_PORT=8080`·`TERMFLOW_DB_PORT=5434`)을 `.env`에 적어 접속 주소를 그대로 둔다. 새 기본값으로 옮기려면 그 줄을 지우고 다시 기동한 뒤 방화벽·안내 주소를 바꾼다.

### 14.6 백업·복구·자동 실행
```bash
scripts/backup.sh                       # backup/termflow_yyyyMMdd.dump (같은 날 두 번째는 _HHmmss), 14일 초과 삭제
scripts/backup.sh --keep-days 30
scripts/restore.sh backup/termflow_20261001.dump        # 확인 문구 RESTORE. --force(무인) · --no-app-start
```
동작은 §7·§8의 `.ps1`과 같다(덤프 목차 검증 → 호스트 복사, app 중지 → DB 재생성 → `pg_restore --exit-on-error` → 건수 → app 기동). 덤프 파일 권한은 600.

`install.sh`가 root + systemd에서 등록하는 단위(`/etc/systemd/system/`):

| 단위 | 하는 일 |
|---|---|
| `termflow.service` | 부팅 시 `docker compose up -d --wait`, 중지 시 `docker compose stop`(oneshot). `systemctl status termflow` |
| `termflow-backup.service` + `.timer` | 매일 02:00 `scripts/backup.sh`(꺼져 있어 놓친 회차는 켜질 때 한 번). `systemctl list-timers termflow-backup.timer`, 결과 `journalctl -u termflow-backup` |

systemd가 없거나 root가 아니면: 컨테이너는 `restart: unless-stopped`로 Docker 데몬과 함께 올라온다. 백업은 cron — `0 2 * * * /opt/termflow/scripts/backup.sh >> /opt/termflow/logs/backup.log 2>&1`.
제거: `sudo systemctl disable --now termflow-backup.timer termflow.service && sudo rm /etc/systemd/system/termflow*.{service,timer} && sudo systemctl daemon-reload`(데이터는 `docker compose down -v` 전까지 남는다).

### 14.7 문제 해결(Linux)
| 증상 | 원인·조치 |
|---|---|
| `Docker 데몬에 연결하지 못했습니다` | `sudo systemctl enable --now docker`, 또는 사용자를 `docker` 그룹에 넣고 다시 로그인 |
| `docker compose(v2) 플러그인이 없습니다` | `docker-compose-v2`(Ubuntu) 또는 `docker-compose-plugin`(docker-ce) 설치. 옛 `docker-compose`(v1)는 지원하지 않는다 |
| `termflow-app:… 이미지가 없고 빌드할 소스도 없습니다` | 번들의 `images/` 폴더가 빠졌다 — 번들을 다시 풀거나 `docker load -i images/termflow-images-<판>.tar.gz` |
| app이 healthy가 안 되고 로그에 `EACCES … /app/logs` | 로그 폴더 권한 — `sudo chown 1000:1000 logs migration/report` 후 `./start.sh` |
| 다른 PC에서 접속 안 됨 | 방화벽(§14.4), 클라우드면 보안 그룹. db 포트(7341)는 열지 않는다(§12) |
| 그 밖 | §13과 같다(`docker compose logs --tail 100 app`) |

검증(CR-12 §3): Docker Desktop 위 `docker:dind` 컨테이너를 빈 Linux 서버로 써서 번들 반입 → `install.sh` → 승계 1차 → healthy → v1.0.0 → v1.1.0 업그레이드 → 백업·보관 삭제·복구를 실행했고, systemd 단위는 Ubuntu 24.04에서 `systemd-analyze verify`로 확인했다.
