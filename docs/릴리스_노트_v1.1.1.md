## 1. 변경
| 항목 | 이전 | 이후 | 사유 |
|---|---|---|---|
| 앱 호스트 포트 기본값(`TERMFLOW_APP_PORT`) | 8080 | **7340** | 8080은 Tomcat·Jenkins·Spring Boot·Keycloak·프록시 등의 기본값이라 같은 서버에서 자주 충돌한다 |
| DB 호스트 포트 기본값(`TERMFLOW_DB_PORT`) | 5434 | **7341** | 5432 근처(5433·5434)는 PostgreSQL 두 번째 인스턴스가 흔히 쓴다 |

- 바뀐 것은 **설치본의 호스트 포트 기본값**(compose·`install.sh`·`start.sh`·`start.ps1`·`.env.example`)뿐이다. 컨테이너 안 포트(app 8080 · db 5432)와 개발 실행(`pnpm dev` 서버 8080 · vite 5173)은 그대로다.
- 7340·7341은 흔한 서비스·개발 도구 기본값 목록(웹 서버·WAS·DB·메시지 큐·모니터링·CI 등)과 대조해 겹치지 않는 값으로 골랐다.

## 2. 기존 설치 업그레이드(자동 유지)
`.env`에 포트를 적지 않고 옛 기본값으로 떠 있던 설치는 `start.sh`(Linux `install.sh`가 부른다)·`start.bat`이 **기동 전에** 옛 값을 `.env`에 적는다 — 접속 주소·방화벽 규칙이 바뀌지 않는다.
```
# v1.1.1 기본 포트 변경 전 설치 — 접속 주소 유지(CR-12 C16). 새 기본값 7340로 옮기려면 이 줄을 지운다
TERMFLOW_APP_PORT=8080
```
새 기본값으로 옮기려면 그 줄을 지우고 다시 기동한 뒤 방화벽·사용자 안내 주소를 바꾼다. `.env`에 포트를 이미 적어 둔 설치(예: 운영 `termflow-prod` 8090·5436)는 영향이 없다.
`docker compose up`을 직접 쓰면 이 고정 처리가 돌지 않으므로 업그레이드는 스크립트로 한다.

## 3. 개발 PC
`.env.example`의 `TERMFLOW_DB_URL`이 `localhost:7341`이 됐다. 이미 쓰던 개발 PC는 `.env`에 `TERMFLOW_DB_PORT=5434`를 두면 기존 개발 DB 포트를 그대로 쓴다.

## 4. Linux 파일 옮기기·업그레이드 절차(가이드 §14.2·§14.5)
- 가이드에 **번들을 서버로 옮기는 절차**(`scp` 두 파일 → `ssh` → `/tmp/`에서 체크섬 → 처음 설치)를 넣었다. SSH가 막힌 폐쇄망은 USB 등으로 같은 두 파일.
- **`scripts/upgrade.sh`** 추가 — 업그레이드를 한 줄로: `sudo bash /opt/termflow/scripts/upgrade.sh /tmp/termflow-linux-<판>.tar.gz`(체크섬 → 백업 → 풀기(이전 판 이미지 파일 정리) → `install.sh --migrate no`). v1.1.0 이하 설치는 처음 한 번만 수동(백업 → 풀기 → `install.sh --migrate no`)으로 올리고 다음부터 한 줄.
