## 1. 변경

### 1.1 범용 기본 표준 템플릿(CR-16)
| 항목 | 내용 |
|---|---|
| 기본 표준 STDV1 | 새 프로젝트의 기본 원본 "TermFlow 기본 표준 v1"을 어느 조직에서나 쓸 수 있는 범용 데이터로 새로 만들었다 — 업무구분 10(공통·시스템·인사·회계·예산·계약·전자결재·영업·판매·구매·재고·물류) · 용어 1,316 · 도메인분류 71 · 도메인 1,020 · 코드구분 104 · 코드 541 · 기본컬럼 2세트(표준 감사 8 · 간단 감사 4). **검토필요 0건** |
| 데이터 정리 | 승계 사전의 오류를 고쳤다 — 물리약어 오타(`STAUS`), 뜻이 다른데 같은 물리약어(제안자/속성, 주문/발주/순서, 입사/가입 등 30여 건), 이름이 뜻과 다른 도메인분류 4, 숫자 든 도메인·물리명 충돌, "0형" 혈액형, 이름이 숫자뿐인 코드구분, 3벌이던 결재상태. 기관 고유 운영 코드(회의실·차량 등)와 업종 전용 용어·도메인은 범용에서 뺐다 |
| 표준 코드 | 성별(ISO/IEC 5218)·요일(ISO 8601)·통화(ISO 4217)·국가(ISO 3166-1)·언어(ISO 639-1)·시도(행정표준코드)·은행(금융결제원 코드) |
| 적재 | 이미지에 든 CSV(`apps/server/resources/templates/stdv1/`)로 **서버 첫 기동 때 한 번** 만든다. 승계를 하지 않은 설치에도 기본 템플릿이 생긴다. 품질 검사(Q1~Q8) 위반 0건일 때만 넣고, 관리자가 지운 뒤에는 다시 만들지 않는다 |
| 패션·유통 표준 RETAILV1 | 승계로 만든 표준 사전(용어 1,705·도메인 4,587 등)은 키 `RETAILV1` "패션·유통 표준 v1"로 남는다. 패션·유통 업종 프로젝트는 마법사에서 이 템플릿을 고른다 |
| 승계 | 1차 결과 템플릿 키가 `RETAILV1`로 바뀌었다(대사 리포트 열 `stdv1_cnt` → `template_cnt`). `start.bat`·`start.sh`는 RETAILV1(또는 이전 판이 승계로 만든 STDV1)과 RMS로 승계 완료를 판정한다 |

| 오류 토스트 | 오류도 8초 뒤 닫힘, 같은 문구는 묶음, 최대 3개 — DDL 패널 버튼을 가리던 문제 |

## 2. 업그레이드
평소 절차(가이드 §6 Windows · §14.5 Linux `upgrade.sh`)로 올린다. 업그레이드 후 **첫 기동 때 자동으로**:
1. 이전 판이 승계로 만든 템플릿 STDV1을 **RETAILV1 "패션·유통 표준 v1"** 로 키·이름만 바꾼다. 데이터, RMS, 그 템플릿으로 만든 프로젝트는 그대로다.
2. 범용 기본 표준 **STDV1**을 새로 만든다.

확인: app 로그 `옛 승계 템플릿 STDV1 → RETAILV1 …`, `기본 표준 STDV1 적재 — 업무구분 10 · 용어 1316 …`, [시스템 › 템플릿]에 두 템플릿.

- 승계 템플릿 화면 주소를 즐겨찾기했다면 `/projects/STDV1/…` → `/projects/RETAILV1/…`.
- 승계 데이터 정정(검토필요 도메인)은 RETAILV1에서 이어서 한다(가이드 §4.4).
- `.env`에 `TERMFLOW_APP_PORT`가 있으면 로그인 쿠키 이름이 바뀌어 업그레이드 후 **한 번 다시 로그인**한다.

## 3. 알려진 제한
- 편집기·팝오버 레이아웃 정리(CR-15 T15.7)는 다음 판에 들어간다.
- 소개 사이트·설명서 그림은 이전 데모 데이터로 찍은 그대로다.
- Release는 **초안**으로 만들어진다 — 첨부 파일을 확인한 뒤 게시한다. Windows용 배포물(이미지 포함 zip)은 아직 없다.
