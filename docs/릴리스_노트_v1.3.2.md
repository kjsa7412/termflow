## 1. 변경

### 1.1 테이블 설계 프롬프트 `design_table`
| 항목 | 내용 |
|---|---|
| 인자 순서 | 에이전트 클라이언트가 명령 뒤 인자를 공백으로 나눠 넘기므로, 한 단어 값을 앞에 둔다 — `projectKey`(필수) · `bizArea`(선택) · `requirement`(선택). 예: `/termflow:design_table QATEST RP` |
| 요구사항 | 요구사항이 없거나 잘려 보이면 에이전트가 도구를 부르기 전에 목적·컬럼 항목·키를 먼저 묻는다 |

### 1.2 설명서(사용자 가이드 §9.3)
- 명령 목록에 보이는 이름은 `/termflow:design_table (MCP)`(전체 이름 `/mcp__termflow__design_table`도 실행된다). 목록에 없을 때 확인할 것과, 프롬프트를 목록에 보여 주지 않는 클라이언트에서는 그냥 요청하면 같은 순서로 진행된다는 안내.

## 2. 업그레이드
v1.3.1에서 바뀐 DB·설정은 없다. 평소 절차(가이드 §6 Windows · §14.5 Linux)로 올린다.
```bash
sudo bash /opt/termflow/scripts/upgrade.sh /tmp/termflow-linux-1.3.2.tar.gz
```
에이전트 쪽은 다시 등록할 필요 없다 — 새 세션을 열면 바뀐 인자가 보인다.

v1.3.0 §3과 같다.
